Scope

What we're building

In zooryapay-merchant

  • A new "Events" tab in the E‑commerce hub — same tab‑strip pattern as Products, Inventory, Bookings.
  • No new sign‑in screen — the merchant's existing session is the credential into EMS.

EMS backend (new service)

  • Event — venue, date/time, capacity, status; single date or multi‑date schedule.
  • Ticket types — tiered pricing, per‑type/per‑date capacity, sale windows, registration questions.
  • Order — multi‑ticket cart, promo codes, priced server‑side.
  • Public buyer storefront, reached through the gateway's public route.
  • Check‑in — camera/manual scan, live counts synced across devices.
  • Event‑level reporting — daily sales, per‑tier breakdown, CSV export.

Payment — Zoorya Pay only

  • EMS starts a hosted‑checkout session per order — same contract the booking‑link flow already proves out.
  • Money settles straight into the organiser's existing wallet — no separate EMS‑side payout.
  • Refunds route through Zoorya Pay's existing refund mechanism.
Reused as‑is

Withdrawals, Payout accounts, Balance, Transactions, Reports, and the E‑commerce dashboard — ticket revenue shows up automatically the moment it's in the wallet, since these are all wallet‑level views already. Nothing new to build here.
